# Save · Narrative 精简版 0.2.3

用于手机浏览器中 SillyTavern 的一对一纯文字聊天。基于 Lol1p0p 的 Narrative Agent 0.2.1（MIT）裁剪，保留原版 Relay → 后台生成 → 每轮摘要，以及原文召回与 n+m 近期原文窗口。之前的 Save 0.1.0 不再使用。

## 本次修复

- 回复、规划、摘要和 Relay 均有等待上限。取消与关闭接管会中止本插件的 raw 请求，并拒绝迟到结果写回。
- 流式 Relay 完成后的“生成中”标志不会被恢复成旧值；失败、停止或超时后调用原生按钮恢复接口。
- 每轮开始即建立执行记录，标明当前步骤、实际模型、流式设置、请求状态和拦截原因。Relay 未生成消息时也不会留下上一轮成功记录。
- 正文和模型返回的思考先保存，再分析摘要。最终保存脱离生成锁，保存等待不会让发送按钮持续不可用。
- 仍使用酒馆原生保存顺序；封装函数返回后，如没有明确成功回执，会只读核对服务端聊天内容。未确认保存时保留备份，不误报成功。
- 扩展面板新增“导出未保存备份”和“重试保存当前聊天”。备份为酒馆聊天 JSONL，可独立留存。
- 保留预设中 system、user、assistant 的角色和启用顺序；把原生编译提示中的静态 system 注入、已识别的预设和命名示例带入后台，减少世界书/作者注释被遗漏的问题。
- 不删除原始聊天，不清空摘要，不把“正在生成回复……”写进正文。模型实际返回的思考继续按酒馆原生显示与解析设置保存。

Google 等服务商仍可能拦截具体请求。本版会记录发生阶段并结束对应流程，不自动改写内容、调整安全设置、换模型或重复生成来绕过拦截。

## 安装和更新

1. 解压 ZIP，用包内的 save 目录完整替换实际运行酒馆的扩展目录。manifest.json、index.js、lifecycle.js、persistence.js、response.js 应在同一层。
2. 如果你通过自己的 GitHub 仓库安装：把 save 目录内的全部内容上传到原仓库中 manifest.json 所在的那一层，再在酒馆管理扩展中更新。
3. 关闭原 Narrative Agent、旧 Save、Horae、内置自动总结与其他自动裁剪插件。Token 监测插件可以保留。
4. 刷新手机网页。扩展标题应为“Save · Narrative 精简版 0.2.3”；若仍为旧版本，重新加载网页缓存即可，不需要清除聊天或摘要。

支持酒馆 Chat Completion 类别下的 Gemini、Claude、OpenAI 兼容服务等连接。ZIP 不是 Git 仓库地址，不能直接填进 Git URL 安装框。文件应安装到实际运行服务的酒馆目录；不是仅上传 ZIP 就完成安装。

## 省 Token 路线

每轮先用原生请求取得 Relay 标记，再通过酒馆 raw 通道生成正文，最后分析本轮并保存逐轮摘要。默认通常为 3 次模型请求；开启原文召回通常为 4 次。接入缺少摘要的旧聊天时可能增加历史分析请求。没有改成“攒够若干轮才摘要”的另一种技术路线。

后台发送角色设定、已识别的原生静态提示/预设、用户设定、历史摘要、近期原文和当前输入。被拦或未摘要的历史不会静默删除，离开近期窗口后仍可能以原文保底。因而“摘要不重试”不等于该历史内容从后续生成输入中消失。

近期原文窗口沿用原版算法与参数：写作基础 3 轮、增长余量 6；规划基础 4、余量 5。窗口逐步增长，再按原规则回缩。源码对应见 SOURCE-MAP.md；原版方法及 SummaryStore 有对照测试。

原生流式开关可以开启，但后台 raw 生成仍为非流式：思考和正文在后台请求完成后显示，不是逐字直播。关闭插件后恢复酒馆原生生成。

预设和静态注入的保留不等同于逐字复现原生最终提示；动态注入、复杂扩展及特殊角色位置仍需按实际配置核对。执行记录保留原生提示长度/角色结构/指纹与后台角色结构，不默认导出私人提示全文或 API 密钥。

## 请求超时

| 步骤 | 默认上限 |
|---|---:|
| Relay | 60 秒 |
| 回复生成 | 180 秒 |
| 规划与摘要 | 90 秒 |
| 保存等待 | 10 秒 |

回复、规划与摘要的等待上限可在面板调整。超时不会自动再发一笔同样的付费请求；短暂网络故障仍最多重试一次。任何停止或超时均不能撤销服务商已经产生的费用。

## 未保存时怎么办

状态若提示“尚未确认保存”，可以先点击“导出未保存备份”，再点击“重试保存当前聊天”。备份只在当前浏览器本地保存，不会自动上传外部服务。服务端确认保存了最新消息后清除对应备份。

浏览器存储已满、不可用或处于特殊隐私模式时，备份可能只保留在当前页面内存。遇到未保存提示应先导出，避免关闭或刷新页面。备份完整保留，不会为了塞进存储而静默截断。已发出的保存请求可能稍后结束，后续写入保持顺序，生成界面不等待它恢复。

## 聊天与功能边界

- 摘要保存在 message.extra.save_na 和对应 swipe_info，正文只显示回复。沿用 schema 2，可读取 0.2.2 以及原 Narrative Agent 的部分旧摘要格式。
- 普通发送、续写、滑动和重生成均保留原生消息结构。编辑历史后，来源不一致的后续摘要会失效。
- 当前聊天独立保存摘要，原文召回只查当前聊天；没有跨聊天或跨设备同步。
- 群聊、静默生成、代用户生成以及含图片、附件或工具结果的聊天不接管。
- 删除骰子、库存、任务、数值关系、时钟、MVU 和跑团工具链。
