# Save · Narrative 精简版 0.2.1

0.2.1 显示修正：后台生成时不再往聊天正文写入“正在生成回复……”。生成进度仍可在扩展设置内查看；原版请求链路、窗口算法和已存摘要格式不变。覆盖更新后刷新网页即可，不需要清除现有摘要。

这是基于本地 Narrative Agent 0.2.1 源码裁剪的酒馆扩展，用于手机浏览器里的一对一纯文字聊天。原版代码来源、保留的算法和修改位置见 [SOURCE-MAP.md](SOURCE-MAP.md)。之前的 0.1.0 定期压缩版本不再使用。

## 保留的核心机制

1. `CHAT_COMPLETION_PROMPT_READY` 接管原生提示，将其替换成原版的两条 Relay 消息，要求返回 `__NA_PLACEHOLDER__`。
2. 原生请求结束后，由 `GENERATION_ENDED` 启动原版后台生成链路，调用酒馆的 `generateRaw({ prompt: messages })`。
3. 默认采用原版“无规划工具”的合并生成模式：角色设定、启用的预设、用户设定、所有已保存的逐轮摘要、近期原文和最新输入组合后生成回复。
4. 每轮回复后立即调用分析模块，追加该轮摘要。这里没有“累计8条才启动”的规则。
5. 原样保留 `_getStableRecentTurns(n,m)` 窗口算法和默认值：回复 n=3、m=6；召回规划 n=4、m=5。窗口会随对话增长，到 n+m 以上时删除前 m+1 轮，再增长。
6. 可选原文召回仍使用“规划→选择轮次原文→写作→分析”路线，默认关闭，与原版相同。

默认一轮通常有 **3 次请求：Relay＋回复生成＋摘要分析**；启用召回通常为4次。首次读取开场白、接入未摘要的旧聊天或网络重试可能增加请求。全部请求都会显示在本插件的执行记录中。记录里的字符数不是服务商计费 Token 数；本插件不保证监测插件显示的“38 tokens”代表全部费用，也不保证每轮都更便宜。

## 按你的用途删改

- 删除骰子、检定、任务、库存、数值关系、游戏时钟、MVU变量、世界书工具及相关面板/教程。
- 删除工具调用和工具后处理，因此不保留依赖这些工具的“并行执行”开关。
- 调整写作提示词为日常角色对话，删除原版额外的思考格式要求。
- 回复仍写进酒馆原生消息气泡；`mes` 只放正文。摘要及内部编号保存在 `message.extra.save_na` 和对应 `swipe_info`，跟随聊天保存；不显示在正文中。
- 修复原版角色卡未接入生成、预设读取跳过主提示、空预设判空、普通开场白被遗漏等问题。
- 重生成/滑动排除被替换回复的旧摘要，续写保留原回复并重新摘要同一轮；编辑旧消息后，依赖它的摘要失效。
- 不删除聊天原文，不调用 `/hide`。停用后直接使用酒馆原生请求和原始记录。

## 安装或替换旧版

1. 停用原 Narrative Agent、Save 0.1.0、Horae、酒馆内置自动总结及其他自动裁剪插件。Token监测插件可以保留。
2. 用 ZIP 内的 `save` 目录完整替换实际运行酒馆的 `public/scripts/extensions/third-party/save`。`manifest.json` 必须直接位于该目录，不要嵌套成 `save/save/manifest.json`。
3. 刷新手机酒馆网页；如仍显示旧界面，清除该网页缓存后重载。新版面板标题为 **Save · Narrative 精简版 0.2.1**。
4. 使用酒馆的 Chat Completion 连接（包括这个连接类别下的 Gemini、Claude、自定义 OpenAI 兼容服务等），保持你原来的模型/API设置。
5. 默认启用，可照常发消息。完成后状态应显示“本轮3次请求，已保存…条摘要”。状态和执行记录能区分“已加载”与“实际执行完成”。

ZIP 是文件安装包，未发布 Git 仓库地址，不能把本地 ZIP 路径填进酒馆的 Git URL 安装框。你若通过手机浏览器连接远端酒馆，文件要安装在远端服务端；酒馆若运行在手机本地，则放进手机的酒馆目录。模块均用相对路径，不调用原版硬编码的 HTML 模板路径。

## 当前聊天与旧聊天

新聊天从新摘要开始，当前没有跨聊天自动迁移。兼容读取原 Narrative Agent 的 `<context>`、`<summary>` 记录，不批量改写你的旧消息。

普通旧聊天缺少摘要时，每次生成前至多补一批历史摘要（最多6轮、合计10000字符）。未成功摘要且已离开近期窗口的内容仍以原文携带，不会静默丢掉。这个兼容步骤会额外调用模型，执行记录会标注 `history-analysis`；正常新对话仍是原版的逐轮分析机制。过长的单轮记录不会被偷偷截断。

本版只处理一对一文字对话。群聊、静默请求、代用户生成和带附件/工具结果的历史保持原生流程。后台生成期间使用酒馆原生停止按钮；切换聊天会丢弃旧流程返回结果，避免写入新聊天。停止无法撤销已经产生的服务商费用。

## 已验证的范围

- 25项离线测试：真实桥接类、路由、生成和摘要模块完整执行；对照原版源码验证窗口方法完全一致，并对300组历史/窗口组合比较结果。也验证了长历史离开近期窗口后以摘要代替原文。
- 独立 SillyTavern **1.18.0** + Edge/Chromium：加载扩展，连续发送、摘要保存、下一轮读取、续写、滑动回复、重生成、关闭后恢复原生请求和手机宽度设置面板。测试使用真实酒馆前后端，仅将模型响应替换为本地模拟数据，阻止所有外部网络请求。
- 390×844手机视口下没有面板横向溢出，按钮可正常显示；实际测试记录和图片保存在 `tests/evidence/`。

**尚未验证你的 Android 实机、你的模型输出质量及真实账单。** 原版路线的 Relay、后台生成与分析都保留，真实费用需要累计全部请求。较长聊天的逐轮摘要总量仍会增长，这是原版机制的限制，后续的 `memory` 插件另行处理长期记忆。
